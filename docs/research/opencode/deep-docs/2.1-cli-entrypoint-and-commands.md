This document describes the CLI entrypoint, command routing system, bootstrap process, and command implementations. It covers how OpenCode starts, parses arguments, initializes the project instance, and dispatches to various command handlers.

For information about the TUI application itself (UI components, rendering), see [Terminal User Interface (TUI)](https://deepwiki.com/anomalyco/opencode/3.1-terminal-user-interface-(tui))
. For the HTTP server started by `serve` and `web` commands, see [HTTP Server & REST API](https://deepwiki.com/anomalyco/opencode/2.6-http-server-and-rest-api)
. For configuration loading and hierarchy, see [Configuration System](https://deepwiki.com/anomalyco/opencode/2.2-configuration-system)

The TUI runs in a separate worker thread to isolate the UI from the server and improve stability. This architecture is implemented in `TuiThreadCommand`.

**Sources:** [packages/opencode/src/cli/cmd/tui/thread.ts24-53](https://github.com/anomalyco/opencode/blob/7daea69e/packages/opencode/src/cli/cmd/tui/thread.ts#L24-L53)

### RPC Methods

The worker exposes these RPC methods at [packages/opencode/src/cli/cmd/tui/worker.ts100-144](https://github.com/anomalyco/opencode/blob/7daea69e/packages/opencode/src/cli/cmd/tui/worker.ts#L100-L144)

**Sources:** [packages/opencode/src/cli/cmd/tui/worker.ts100-144](https://github.com/anomalyco/opencode/blob/7daea69e/packages/opencode/src/cli/cmd/tui/worker.ts#L100-L144)

### Transport Selection

The TUI can use two transport modes:

**Internal Transport** (default)

*   `fetch`: RPC-proxied requests to worker
*   `events`: RPC-forwarded event stream
*   No network exposure
*   Faster startup

**External Transport** (`--port`, `--hostname`, or `--mdns` flags)

*   `url`: Actual HTTP URL
*   `fetch`: Standard HTTP fetch
*   `events`: Server-sent events
*   Accessible from network

**Sources:** [packages/opencode/src/cli/cmd/tui/thread.ts172-190](https://github.com/anomalyco/opencode/blob/7daea69e/packages/opencode/src/cli/cmd/tui/thread.ts#L172-L190)

Network Configuration
---------------------

Server-based commands (`serve`, `web`, `acp`) support network configuration through the `withNetworkOptions()` helper.

### Network Options

**Sources:** [packages/opencode/src/cli/network.ts1-61](https://github.com/anomalyco/opencode/blob/7daea69e/packages/opencode/src/cli/network.ts#L1-L61)

### Option Resolution

The `resolveNetworkOptions()` function at [packages/opencode/src/cli/network.ts39-60](https://github.com/anomalyco/opencode/blob/7daea69e/packages/opencode/src/cli/network.ts#L39-L60)
 applies this precedence:

1.  Explicit CLI flags take highest priority
2.  Config file values (`server.port`, `server.hostname`, etc.)
3.  Default values
4.  Special case: if `--mdns` is enabled and hostname not set, defaults to `0.0.0.0`

### Network Configuration Table

| Option | Config Key | CLI Flag | Default | Description |
| --- | --- | --- | --- | --- |
| Port | `server.port` | `--port` | `0` (random) | TCP port to bind |
| Hostname | `server.hostname` | `--hostname` | `127.0.0.1` | Network interface to bind |
| mDNS | `server.mdns` | `--mdns` | `false` | Enable Bonjour/mDNS discovery |
| mDNS Domain | `server.mdnsDomain` | `--mdns-domain` | `opencode.local` | Advertised mDNS hostname |
| CORS | `server.cors[]` | `--cors` (array) | `[]` | Additional CORS origins |

The `win32DisableProcessedInput()` function must run before any Worker spawn or async work to prevent the Windows console from killing the entire process group on Ctrl+C events.
